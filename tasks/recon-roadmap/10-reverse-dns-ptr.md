# Reverse DNS и forward-confirmed PTR

Фаза: 3 — Обогащение идентичности активов
Статус: Выполнено (выпущено в 0.11.0, 2026-11-08)
Зависит от: — (обогащает результаты хостов из Фаз 1–2)
Роадмап: docs/recon-roadmap.md (Фаза 3)

## Цель

Добавить опциональное обогащение результатов reverse DNS и forward-confirmed PTR (`--resolve-ptr`): для каждого живого хоста получить PTR-запись и подтвердить её прямым разрешением обратно на IP. Это дешёвая идентичность, которой нет в собственном структурированном выводе Asphyxia; глубокий разбор сервисов остаётся за хендоффом в `nmap`.

## Область

- Резолвить PTR для найденных IP; forward-confirm: разрешить полученное имя обратно в A/AAAA и проверить, что исходный IP присутствует (иначе пометить как unconfirmed).
- Обогащение опционально и управляется независимым флагом; по умолчанию выключено (DNS добавляет задержку и трафик).
- Ошибки DNS (NXDOMAIN, таймаут, отказ) не аннулируют базовый результат по хосту/порту — обогащение best-effort.
- Разделять факт и вывод в структурированном выводе: `ptr` (наблюдаемая запись) и `ptr_confirmed` (булев результат forward-confirm) — отдельные поля со стабильными именами.
- Уважать таймауты и конкурентность; медленный резолвер не должен стопорить скан (bounded, с собственным таймаутом).

## Критерии приёмки

- [x] `--resolve-ptr` добавляет `ptr` и `ptr_confirmed` в структурированный вывод для хостов с PTR-записью.
- [x] Хост без PTR или с проваленным forward-confirm по-прежнему сообщается: поля отсутствуют или `ptr_confirmed: false`.
- [x] Таймаут DNS ограничен отдельным worker-таймаутом; зависший резолвер не удлиняет основной скан сверх бюджета.
- [x] Поведение по умолчанию (флаг не задан) не меняется: DNS не выполняется.
- [x] Тесты покрывают forward-confirm (совпадение/несовпадение), таймаут worker-а, безопасный PTR-lookup и рендер полей в CSV/JSON.

## Вне области

- Полный DNS-энумератор (перебор поддоменов, zone transfer).
- Кэширование DNS между запусками.


## Реализация

- `src/dns.rs` — PTR через `getnameinfo` (IPv4/IPv6), forward-confirm через `ToSocketAddrs`, каждый lookup в worker-потоке с `recv_timeout`; ошибки/таймаут дают отсутствие полей, а не ошибку скана.
- `src/scanner/address.rs` / `src/main.rs` — `HostHit.ptr`/`ptr_confirmed`, `--resolve-ptr` на `as`, параллельное обогащение живых хостов.
- `src/output/mod.rs` — поля и колонки `ptr`, `ptr_confirmed` во всех форматах; текст показывает PTR и `(unconfirmed)`.
- README/`--help` обновлены; DNS-тесты изолированы от внешней сети (numeric forward-confirm, timeout, безопасный вызов).
