# Комбинированные режимы обнаружения

Фаза: 2 — Улучшение обнаружения хостов
Статус: Выполнено (ветка feat/recon-roadmap, 2026-11-08; `auto` — opt-in)
Зависит от: 06-arp-discovery, 07-icmp-discovery, 08-discovery-ports
Роадмап: docs/recon-roadmap.md (Фаза 2)

## Цель

Позволить несколько проб обнаружения за один запуск (`--discovery arp,icmp,tcp`) и сообщать, какая проба подтвердила каждый хост.

## Область

- Слой оркестрации, запускающий выбранные пробы против каждого кандидата и мёржащий результаты; первый положительный вердикт побеждает. Сохраняются подтвердившая проба и (для `--show-down`) последний ICMP-негатив; полная матрица исходов всех проб не хранится (осознанное упрощение).
- Разумный автоподбор: ARP предпочтителен для локального IPv4, ICMP где разрешён, TCP как непривилегированный откат — с явным дефолтом `--discovery auto`, который логирует свой выбор.
- Держать машиночитаемое поле «какая проба подтвердила хост» стабильным для автоматизации; отдельные поля исхода каждой пробы не добавлялись.
- Сохранять лимиты скорости и конкурентность между типами проб (общий бюджет, не per-probe лимиты).

## Критерии приёмки

- [x] `--discovery arp,icmp,tcp` сообщает хосты, найденные любой пробой, и называет подтвердившую пробу в поле `discovery`.
- [x] Отказы проб (нет локальной IPv4-сети, нет root/CAP_NET_RAW, IPv6) деградируют в предупреждения; оставшиеся пробы продолжают работу.
- [x] Хост, пропущенный TCP, но найденный ARP/ICMP, появляется в результатах с записанным основанием (`discovery: "arp"|"icmp"`, MAC/OUI для ARP).
- [x] Детерминированный порядок (сортировка по IP) и стабильные имена полей во всех форматах вывода.
- [x] Тесты покрывают разрешение плана (`auto`, дедупликация, запрет смешивания), деградацию комбинированного режима и общий пейсер (существующие rate/delay-тесты); живой merge ARP/ICMP требует root и проверяется вручную.

## Вне области

- OS-fingerprinting по комбинациям проб.


## Реализация

- `src/cli/mod.rs` — `--discovery` принимает `value_delimiter = ','` и список режимов; добавлен `auto`.
- `src/main.rs` — `resolve_discovery_plan` (auto → arp,icmp,tcp; дедупликация; auto только один), `scan_discovery` (специализированные одиночные пути) и `scan_hosts_combined` (последовательный перебор проб на адрес, первый положительный результат, предупреждения и удаление недоступных проб, общий rate/delay-бюджет, сортировка).
- Отрицательный ICMP-вердикт сохраняется как `reason` и выдаётся через `--show-down`, если более поздняя проба не подтвердила хост.
- `auto` не сделан дефолтом осознанно: дефолт остаётся непривилегированным `tcp`, чтобы обычный запуск не пытался открывать raw-сокеты и не шумел предупреждениями.
