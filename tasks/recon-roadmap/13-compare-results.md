# Сравнение двух файлов результатов

Фаза: 4 — Разведка во времени
Статус: Выполнено (выпущено в 0.11.0, 2026-11-08)
Зависит от: — (работает по стабильному `ScanRecord` из `src/output/mod.rs`)
Роадмап: docs/recon-roadmap.md (Фаза 4)

## Цель

Добавить режим сравнения двух файлов структурированных результатов (`asphyxia diff <old.json> <new.json>`), сообщающий новые и исчезнувшие хосты, порты, сервисы и баннеры.

## Обоснование выбора источника

Сравнение работает по структурированному выводу (`ScanRecord`: `ip`, `port`, `proto`, `status`, `service`, `banner`), а не по state-файлам возобновления. Причина зафиксирована после валидации `src/resume.rs`: `ScanState.findings` хранит только open-находки, `is_compatible` (`resume.rs:82`) требует совпадения targets/ports/порядка, а хост живёт как индекс без явного up/down. Из state нельзя вывести «исчезнувшие хосты» и нельзя сравнить сканы с разными наборами портов. `ScanRecord` этих ограничений не имеет и стабилен между форматами. `src/resume.rs` не трогаем — он остаётся под возобновление.

## Область

- Читать два файла результатов (JSON-массив `ScanRecord`; при необходимости поддержать JSONL) и строить diff.
- Единица идентичности — `(ip, port, proto)`; хост-уровневые изменения — по множеству `ip`.
- Категории diff: новые/исчезнувшие хосты (set difference по `ip`), новые/исчезнувшие порты, изменения `status`, изменения `service`, изменения `banner`.
- «Исчезнувший хост» = присутствует в старом файле, отсутствует в новом (предполагается совпадающая область целей; предупреждать, если области явно расходятся).
- Детерминированный, стабильный вывод; сам diff доступен в машинных форматах (JSON/JSONL) для нижестоящих инструментов.

## Критерии приёмки

- [x] `asphyxia diff old.json new.json` сообщает новые/исчезнувшие хосты, порты, изменения status/service/banner.
- [x] Идентичность по `(ip, port, proto)` стабильна; переупорядочивание входных файлов не создаёт ложных изменений (юнит-тест).
- [x] Diff эмитится в JSON Lines как поток событий (`new_host`, `removed_host`, `new_port`, `removed_port`, `changed`, `warning`).
- [x] Пустой файл, непересекающиеся host-множества или разные протоколы дают видимое предупреждение о возможном расхождении области.
- [x] Тесты покрывают новые/исчезнувшие хосты и порты, изменения полей, стабильность порядка, JSONL, JSON-массив/JSONL-загрузку и CLI-ошибки.

## Вне области

- Сравнение более двух файлов сразу.
- Diff по state-файлам возобновления (осознанно не поддерживается — см. обоснование).


## Реализация

- `src/diff.rs` — `InputRecord` (Deserialize, игнорирует незнакомые поля), `Record`, `DiffReport`, `compare`, `render_text`, `render_jsonl`; сравнение по `(ip, port, proto)`, сортировка всех списков.
- `src/cli/mod.rs` / `src/main.rs` — подкоманда `diff <old> <new>` с `-o text|json|jsonl` и `--output-file`; CSV/grep отвергаются.
- Предупреждения: пустой набор, непересекающиеся host-множества, разные proto-наборы; для JSON/JSONL дублируются в stderr.
- `resume.rs` не тронут: сравнение сознательно работает по результатам, а не по state.
