# Настраиваемый source-порт

Фаза: 1 — Расширение семейства сканирований
Статус: Выполнено (ветка feat/recon-roadmap, 2026-10-29; релиз не выпущен)

Роадмап: docs/recon-roadmap.md (Фаза 1)

## Цель

Позволить оператору фиксировать source-порт raw TCP-проб (`--source-port <PORT>`), чтобы проверять firewall-правила, привязанные к source-порту (например, ACL, разрешающие исходящий трафик с 53, 80 или 443). Для аудита собственной инфраструктуры это способ подтвердить, что правила фильтрации ведут себя как настроены, а не маскировка трафика.

## Область

- Пробросить опцию source-порта через конструкторы пакетов в `src/scanner/syn.rs`. Сейчас `src_port_for(dst_port)` выбирает отдельный эфемерный порт на каждый сканируемый порт (`syn.rs:224`); режим фиксированного порта заменяет это.
- **Оговорка про матчинг ответов:** с фиксированным source-портом ответы уже нельзя атрибутировать только по source-порту. Расширить матчинг `SynReceiver` на destination-порт ответа (сканируемый порт) и/или сериализовать пробы на хост по необходимости.
- CLI-флаг на `PortScan`, документированный как применимый только к raw-скану (в connect/UDP-режимах игнорируется с предупреждением).
- Привязка к интерфейсу (`-e`) должна продолжать работать с фиксированными source-портами.

## Критерии приёмки

- [x] `asphyxia ps --syn --source-port 53` шлёт пробы с порта 53 и корректно атрибутирует ответы по всем сканируемым портам.
- [x] Без флага поведение не меняется (отдельные эфемерные source-порты).
- [x] Ограничение скорости и конкурентность сохраняются с фиксированными source-портами.
- [x] Тесты покрывают инъекцию source-порта в билдере и атрибуцию ответов при коллизии source-портов.

## Что сделано

- `src/scanner/syn.rs`: `SOURCE_PORT` (OnceLock) хранит запрошенный оператором source-порт; `probe_port` использует его, когда он задан, иначе — per-port эфемерную схему. `reader_loop` ключует ответы по destination-порту ответа (сканируемый порт), когда фиксированный source активен, поскольку все пробы несут один и тот же source и NAT/VPN может переписать его — атрибуция остаётся корректной по всем сканируемым портам.
- `src/cli/mod.rs`: флаг `--source-port <PORT>` на PortScan, документирован как применимый только к raw-режимам; тесты pin'ят парсинг и отклонение нечисловых значений.
- `src/main.rs`: при заданном флаге и raw-режиме устанавливает порт через `syn::set_source_port` до скана; в connect/UDP-режимах печатает предупреждение на stderr и продолжает без него.
- Тесты: юнит — фиксированный source-порт достигает провода на каждой пробе, ответы ключуются по destination-порту при коллизии source-портов; e2e — SYN-скан с `--source-port 53` против loopback (closed или откат), флаг предупреждает и продолжает в connect/UDP, rate-limit пейсинг сохраняется.
