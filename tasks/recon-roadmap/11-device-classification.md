# Лёгкая классификация устройств

Фаза: 3 — Обогащение идентичности активов
Статус: Выполнено (ветка feat/recon-roadmap, 2026-11-08)
Зависит от: 06-arp-discovery (MAC OUI), обогащается баннерами из `src/scanner/service.rs`
Роадмап: docs/recon-roadmap.md (Фаза 3)

## Цель

Выводить лёгкую метку типа актива (`--classify`) из уже собранных сигналов: комбинации открытых портов, баннеров и MAC OUI из ARP. Цель — навигация по описи активов («это похоже на роутер / принтер / гипервизор / контроллер домена»), а не определение версий. Определение версий и скрипты остаются за хендоффом в `nmap` — это классификация, а не сканирование уязвимостей.

## Область

- Правила классификации по наблюдаемым сигналам, без дополнительных проб: например, открытые 139/445/3389 + баннер SMB → Windows-хост; 22 + баннер вендорного SSH → сетевое устройство; 9100/515/631 → принтер; 902/443 + vSphere-баннер → гипервизор; OUI известного вендора → категория устройства.
- Метка — это вывод, а не факт: класть в отдельное поле `device_type` с полем уверенности (`low`/`medium`), рядом с сырыми фактами (порты, баннеры, OUI), не подменяя их.
- Таблица правил и OUI — из поддерживаемых локальных данных; без обращения к сети во время классификации.
- Обогащение опционально и управляется независимым флагом; по умолчанию выключено.

## Критерии приёмки

- [x] `--classify` добавляет `device_type` и `device_confidence` в структурированный вывод, не удаляя и не переписывая сырые поля портов/баннеров/OUI.
- [x] Классификация не делает новых сетевых проб — чистый post-pass по уже собранным `Finding`/OUI.
- [x] Неоднозначные/неизвестные сигнатуры дают `unknown` с `confidence: "low"`.
- [x] Тесты покрывают representative-сигнатуры (Windows, printer, hypervisor, network-device, web-server, unknown), OUI и CLI-вывод.

## Вне области

- Определение версий сервисов и OS-fingerprinting — делегируется хендоффу в `nmap`.
- Risk-hints и вывод об уязвимостях (например, экспозиция SMBv1) — не задача Asphyxia.


## Реализация

- `src/classify.rs` — чистый классификатор `classify_ports` (порты/сервисы/баннеры) и `classify_oui` (локальная таблица VMware/Cisco/Juniper/Canon/HP), `Device { device_type, confidence }`, `unknown`.
- `src/cli/mod.rs` / `src/main.rs` — `--classify` на `ps` и `as`; портовый скан агрегирует открытые порты/баннеры по хосту, address-скан использует OUI из ARP.
- `src/output/mod.rs` — поля `device_type`/`device_confidence` и колонки CSV/grep; текст показывает `[тип/уверенность]`.
- Ограничение: ACK/FIN/NULL/XMAS-состояния не считаются открытыми портами, поэтому классифицируются как `unknown`.
