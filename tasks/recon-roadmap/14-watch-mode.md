# Watch-режим

Фаза: 4 — Разведка во времени
Статус: Выполнено (выпущено в 0.11.0, 2026-11-08)
Зависит от: 13-compare-results (общая логика diff)
Роадмап: docs/recon-roadmap.md (Фаза 4)

## Цель

Добавить watch-режим (`--watch <INTERVAL>`), который пересканирует ту же область с заданным интервалом и эмитит события изменений между последовательными сканами, переиспользуя логику diff из задачи 13.

## Область

- Повторять текущий скан каждые `INTERVAL`; после каждого прохода сравнивать со снимком предыдущего прохода и эмитить только изменения.
- Единица сравнения — `ScanRecord`, как в задаче 13; первый проход задаёт базовую линию (без событий или явное «baseline»).
- Явное условие остановки: `--watch-count <N>` (число проходов) и/или обработка сигнала (Ctrl-C завершает чисто, не оставляя частичного состояния).
- Ограниченное потребление ресурсов: не накапливать историю всех проходов в памяти — держать только предыдущий снимок и текущий; лимиты скорости/конкурентности применяются к каждому проходу.
- События изменений эмитятся в JSON Lines для нижестоящих инструментов (по событию на строку, с меткой времени прохода).

## Критерии приёмки

- [x] `asphyxia ps ... --watch 5m` пересканирует с интервалом и печатает только изменения относительно предыдущего прохода.
- [x] Первый проход помечен событием `baseline` и не выдаётся за изменение.
- [x] `--watch-count N` останавливается после N проходов (baseline = pass 1); Ctrl-C завершает после текущего прохода.
- [x] Память ограничена предыдущим и текущим снимком; каждый проход — обычный скан со своими `--rate`/`--delay`/лимитами.
- [x] События — валидный JSON Lines с `pass` и `timestamp`; есть `no_changes` для пустого прохода.
- [x] Тесты покрывают baseline, `no_changes`/warning, `--watch-count`, невалидный интервал и запрет `--nmap`; детект изменений покрыт тестами `diff`.

## Вне области

- Долговременное хранение истории изменений (это задача нижестоящего инструмента, потребляющего JSONL).
- Алертинг/нотификации по изменениям.


## Реализация

- `src/cli/mod.rs` / `src/main.rs` — `--watch <INTERVAL>` (`ms`/`s`/`m`/`h`, число = секунды) и `--watch-count`; интервал парсится, `0` отвергается.
- Watch-контроллер запускает отдельный процесс `asphyxia ps ...` на каждый проход с принудительным `-o jsonl --output-file <temp>`; это сохраняет всю обычную логику скана (resume не поддерживается, `--nmap`/`--stdin`/`--resume` отвергаются).
- `src/diff.rs` — `events()` для аннотирования событий `pass`/`timestamp`; baseline и `no_changes` формируются в контроллере.
- Память: хранится только `previous` и `current`; temp-файл удаляется после каждого прохода.
