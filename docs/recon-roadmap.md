# Дорожная карта сетевой разведки

Статус: 0.11.0 выпущен 2026-11-08; все задачи 01–16 выполнены (ICMP `filtered` для FIN/NULL/XMAS — Unreleased), кроме опциональной совместимости форматов сканеров. Root-прогон ARP/ICMP/combined на 192.168.55.0/24 подтверждён.

## Миссия

Сделать Asphyxia быстрым, точным и полезным инструментом сетевой разведки. Сканер должен помогать авторизованному оператору отвечать на четыре вопроса:

1. Какие хосты доступны?
2. Какие порты открыты?
3. Какие сервисы и устройства стоят за этими портами?
4. Что изменилось с прошлого скана?

Проект — инструмент разведки, а не фреймворк для эксплуатации. Он не проводит атак на учётные данные, не доставляет payload'ы, не устраивает отказ в обслуживании и не совершает иных разрушительных действий. Основной сценарий — систематический аудит собственной инфраструктуры: оператор сканирует то, чем владеет или что уполномочен проверять.

## Текущий фундамент

Основой для этой дорожной карты служат следующие части текущей реализации:

- `src/scanner/syn.rs` уже даёт конструирование raw-пакетов IPv4, общий приёмник на libpcap/BPF, классификацию ответов и автоматический откат на connect-скан.
- `src/scanner/address.rs` по умолчанию обнаруживает хосты TCP-пробами по портам 80, 443, 22 и 3389; `src/scanner/discovery/arp.rs` и `src/scanner/discovery/icmp.rs` добавляют ARP/ICMP-обнаружение (`--discovery arp,icmp,tcp`, `auto`), `src/scanner/address.rs` — настраиваемые `--discovery-ports`.
- `src/dns.rs` добавляет reverse DNS/forward-confirmed PTR; `src/classify.rs` — лёгкую классификацию устройств; `src/asn.rs` — офлайн-подсказки ASN/cloud.
- `src/diff.rs` сравнивает два файла результатов; `src/report.rs` строит Markdown/HTML; `src/traceroute.rs` — TCP/ICMP traceroute.
- `src/scanner/service.rs` выполняет лёгкий сбор баннеров и идентификацию сервиса.
- `src/scanner/port.rs` поддерживает UDP-режим (`--udp`) с payload-пробами и классификацией ICMP: `open`, `closed`, `filtered`, `open|filtered`.
- `src/scanner/nmap.rs` реализует хендофф в `nmap` для прицельного разбора найденных портов (`-sV -sC` для TCP, `-sU -sV` для UDP); глубокая интерпретация сервисов делегируется ему, а не дублируется в Asphyxia.
- `src/resume.rs` уже персистит состояние скана для возобновления прерванной работы.
- `src/output/mod.rs` уже поддерживает форматы text, JSON, JSON Lines, CSV и greppable; `ScanRecord` — стабильная единица результата для сравнения во времени.

## Принципы проектирования

- **Авторизация прежде всего:** документировать, что сканы запускаются только против систем, которые оператор уполномочен проверять.
- **Неразрушающий по умолчанию:** разведочные пробы не доставляют payload'ы и не пытаются скомпрометировать сервис.
- **Факты важнее догадок:** отделять наблюдаемые факты от выведенных состояний вроде `open|filtered`.
- **Переиспользовать имеющуюся инфраструктуру:** расширять raw-socket/pcap-конвейер прежде, чем добавлять новый сканер.
- **Делегировать глубину, а не дублировать:** прицельный разбор сервисов (версии, скрипты, сертификаты) — задача хендоффа в `nmap`; Asphyxia добавляет только дешёвую структурированную идентичность.
- **Думать об автоматизации:** каждый новый тип скана нуждается в структурированном выводе и стабильных именах полей.
- **Падать заметно:** недоступный метод пробы должен предупреждать и откатываться, где уместно, а не молча заявлять об успехе.
- **Уважать ресурсы:** к новым режимам применяются лимиты скорости, таймауты, ретраи и границы IPv6.

## Фаза 1: Расширение семейства сканирований (выполнено)

Существующая реализация SYN — это платформа классификации пакетов. Сканы FIN, NULL, XMAS и ACK требуют других комбинаций TCP-флагов и правил классификации, а не второго сканера. UDP-пробирование сервисов ложится сюда же: payload-пробы и классификация ICMP port-unreachable (type 3) добавляются к общему UDP-сокету.

### Предлагаемые режимы

- [x] ACK-скан для анализа состояния фаервола и различения `unfiltered`/`filtered`.
- [x] FIN-скан для малозаметного определения закрытых портов.
- [x] NULL-скан для фаерволов, не соблюдающих поведение по RFC 793.
- [x] XMAS-скан с флагами FIN, PSH и URG.
- [x] UDP-пробирование сервисов: payload-пробы для типовых UDP-сервисов (DNS/53, NTP/123, SNMP/161) и обработка ICMP port-unreachable, чтобы отличать `open` от `open|filtered` и `closed`.
- [x] Настраиваемый source-порт для проверки firewall-правил, привязанных к source-порту.
- [x] Задержка и джиттер на хост для контролируемого, щадящего темпа против чувствительных целей (нагрузка на прод, а не сокрытие).

Примечание: пункт про decoy-адреса из первой редакции убран. Для аудита собственной инфраструктуры оператор и есть владелец актива, поэтому обфускация атрибуции не имеет смысла и попадает под запрет evasion из раздела «Вне области».

### Критерии приёмки

- Каждый режим согласованно сообщает `open`, `closed`, `filtered`, `unfiltered` и `open|filtered` — там, где эти состояния применимы к режиму.
- IPv6 откатывается на connect-скан с ясным предупреждением.
- Отказ raw-сокетов и захвата использует имеющийся автоматический откат.
- Режим задержки/джиттера сохраняет ограничение скорости.
- Тесты покрывают флаги пакетов, классификацию ответов и поведение отката.

## Фаза 2: Улучшение обнаружения хостов (выполнено)

Обнаружение только по TCP пропускает хосты, молча отбрасывающие порты 80, 443, 22 и 3389. Добавляем разнообразие проб, сохраняя текущий connect-режим как непривилегированный дефолт.

### Предлагаемые режимы

- [x] ARP-обнаружение для локальных IPv4-сетей (задача 06).
- [x] ICMP echo-обнаружение для сетей, где ICMP разрешён (задача 07).
- [x] Настраиваемые TCP-порты обнаружения (задача 08).
- [x] Комбинированное обнаружение, сообщающее, какая проба подтвердила, что хост жив (задача 09).

### Критерии приёмки

- Режимы ARP и ICMP находят хосты, которые пропускают текущие TCP-пробы.
- Результаты проб остаются машиночитаемыми.
- Неподдерживаемые семейства адресов и ОС падают с полезным сообщением.
- Обнаружение уважает выбор интерфейса, таймаут, ретраи, конкурентность и лимиты скорости.

## Фаза 3: Обогащение идентичности активов (выполнено)

Превратить результаты открытых портов в полезную опись активов, не превращая Asphyxia в сканер уязвимостей. Прицельный разбор сервисов делегируется хендоффу в `nmap` (`src/scanner/nmap.rs`); здесь — только дешёвая структурированная идентичность, которой нет в собственном выводе Asphyxia.

### Предлагаемые обогащения

- [x] Reverse DNS и forward-confirmed PTR-записи (задача 10).
- [x] Лёгкая классификация устройства по наблюдаемым комбинациям портов, баннерам и MAC OUI (из ARP-обнаружения).
- [x] Подсказки по облачному провайдеру и ASN из локальных данных (внешний источник сознательно не реализован).

Примечание: полный сбор TLS-сертификатов и risk-hints (например, экспозиция SMBv1, устаревшие протоколы) из первой редакции убраны — это работа `nmap -sV -sC --script ssl-cert`, дублировать её не нужно. Если оператору нужна глубина, она берётся хендоффом.

### Критерии приёмки

- Обогащение опционально и управляется независимо.
- Факты и выводы — раздельные поля в структурированном выводе.
- Медленный или болтливый сервис не может застопорить скан.
- Ошибки DNS не аннулируют базовый результат по порту.

## Фаза 4: Разведка во времени (выполнено)

Обнаруживать изменения, а не повторно показывать одну и ту же опись. Сравнение работает по структурированным файлам результатов (JSON), а не по state-файлам возобновления.

Примечание к решению: `src/resume.rs` спроектирован под возобновление — он хранит только open-находки в сетке заданий и требует совпадения targets/ports/порядка (`is_compatible`), а хост живёт как индекс без явного признака up/down. Поэтому из state нельзя корректно вывести «удалённые хосты» и нельзя сравнить сканы с разными наборами портов. `ScanRecord` из `src/output/mod.rs` уже несёт `ip`, `port`, `proto`, `status`, `service`, `banner` — это естественная и стабильная между форматами единица сравнения. `resume.rs` оставляем как есть.

### Предлагаемые режимы

- [x] Сравнение двух файлов структурированных результатов (задача 13).
- [x] Отчёт о новых и исчезнувших хостах, портах, сервисах и баннерах (задача 13).
- [x] Watch-режим: перескан с заданным интервалом и эмиссия событий изменений (задача 14).

### Критерии приёмки

- Сравнения детерминированы и работают между форматами вывода.
- Идентичность хоста и порта стабильна между сканами (сравнение по `(ip, port, proto)`).
- Watch-режим имеет явное условие остановки и ограниченное потребление ресурсов.
- Изменения можно эмитить в JSON Lines для нижестоящих инструментов.

## Фаза 5: Топология и отчётность (выполнено)

Добавить контекст, помогающий понять путь и донести результаты.

### Предлагаемые возможности

- [x] TCP- или ICMP-traceroute с полатентностью по хопам и индикаторами потерь (задача 15).
- [x] Отчёты в Markdown и HTML, сгруппированные по хосту, сервису и выведенному типу актива (задача 16).
- [ ] Опциональная совместимость импорта/экспорта с распространёнными форматами данных сканеров (не реализовано, вне обязательного объёма).

### Критерии приёмки

- Traceroute сообщает, где пробирование впервые становится молчаливым.
- Отчёты содержат метаданные скана, область целей, метку времени и версию инструмента.
- Человекочитаемые отчёты строятся из тех же структурированных записей, что и вывод CLI.
- Отчёты не раскрывают секреты и сырые баннеры без необходимости.

## Рекомендуемый порядок реализации

| Порядок | Работа | Причина |
|---|---|---|
| 1 | Сканы ACK, FIN, NULL, XMAS | Переиспользует `src/scanner/syn.rs`; высокая разведочная ценность |
| 2 | UDP-пробирование сервисов | Делит классификацию ICMP type 3 с Фазой 1; закрывает крупную поверхность (DNS/SNMP/NTP) |
| 3 | ARP- и ICMP-обнаружение | Закрывает крупнейший пробел в `src/scanner/address.rs` |
| 4 | PTR и классификация устройств | Малые-средние трудозатраты, высокая ценность для описи активов |
| 5 | Сравнение результатов и watch-режим | Работает по стабильному `ScanRecord`; включает разведку во времени |
| 6 | Traceroute и отчётность | Добавляет топологию и коммуникацию после того, как выстроено качество данных |

## Вне области

- Исполнение эксплойтов и пост-эксплуатация.
- Подбор паролей, credential stuffing, кража токенов.
- Доставка payload'ов и исполнение команд.
- Отказ в обслуживании и исчерпание ресурсов.
- Evasion, нацеленный на сокрытие активности от владельца актива (в том числе decoy-адреса).
- Сканирование целей без явной авторизации.
- Дублирование глубокого разбора сервисов, который уже делает хендофф в `nmap`.
